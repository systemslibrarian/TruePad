TruePad

A true one-time pad — the honest sibling of DeckBook. Every claim on this page is enforced by the open, unit-tested core running live in your browser. Nothing leaves this page.

  • 1 · Key ≥ message Encryption refuses outright when the surviving pad is shorter than the message. No wraparound, no borrowing.
  • 2 · Independent uniform symbols Every pad symbol is a fresh draw from crypto.getRandomValues() with rejection sampling. Never Math.random().
  • 3 · Used exactly once Consuming a symbol deletes it. No API can return a burned value — reuse is impossible, not merely forbidden.

3 Decrypt with the courier's copy

When the pad was generated, an identical copy was “delivered out of band” to the receiver (via serialize() — burned offsets are not present in any form, so the copy can no more reuse them than the original could). The envelope names the pad page and the offsets it used; the copy seeks to that offset, burning everything it skips, and refuses any envelope at or below what it has already burned. Decrypt the same non-empty envelope twice to see a replay refused; encrypt twice and take only the second to see a seek. The envelope is not authenticated: edit its startOffset upward and the copy will burn that far forward — pad can be destroyed from the channel, never reused.

4 The Shannon verdict

One grader, two exhibits, two lines each. Shannon's perfect-secrecy theorem needs all three conditions; the grader below checks your live pad and a DeckBook-style shuffled deck against the same message. The combiner line is the theorem: given the three conditions it is unconditional. The source line is where the symbols came from — and crypto.getRandomValues() is a deterministic generator, so a pad can pass all three conditions and still rest on a computational assumption. That is the honest common case, and this page says so rather than rounding it up.

6 Perfect secrecy is not integrity

A one-time pad is perfectly malleable: adding a delta to a ciphertext letter adds the same delta to what the receiver decrypts, because the key drops out of the difference. Below, a sender has encrypted PAY BOB TEN DOLLARS NOW. The attacker cannot read a single letter — but knows the message format, and that the amount sits at letters 7–9.

What this exhibit is not

Everything above is a correct, bias-free, structurally enforced one-time pad — the strongest claim a browser demo can truthfully make. It is still an exhibit, not a secure messaging tool:

  • The courier is simulated. Sender and receiver pads live in the same browser tab. Real one-time-pad security is mostly key logistics — the physical, out-of-band delivery this page can only gesture at.
  • Burned is burned at the API level, not the physical level. JavaScript cannot zeroize memory; a deleted value lingers until garbage collection. The gold standard destroys the physical pad page.
  • You are trusting the delivered code and the platform CSPRNG. A compromised server or browser is a compromised pad. The real gold standard is an air-gapped machine — dice and paper qualify.
  • Metadata still leaks. Ciphertext length equals message length, and the pad label plus burned offsets reveal traffic volume. Standard for OTP, but worth knowing.
  • There is no integrity protection. Station 6 is live proof. Perfect secrecy and tamper-evidence are separate properties with separate costs.
